# sim, Vim нового поколения

**sim** (также *sim editor*, сокращение от *Secure vIM*) — это Vim нового поколения: написанный с нуля на Rust, он сохраняет модальное редактирование и основные клавиши Vim. Он не читает строки режима, не загружает плагины и не открывает сетевых соединений, а то, что обычно скрыто, выводит на экран: невидимые символы, записи извне редактора, репозитории, которые выполнили бы код.

**Без плагинов. Без строк режима. Без сети.**

Сайт: <https://sim.efg-technologies.com/ru/> · Linux и macOS · MIT OR Apache-2.0 · [История изменений](CHANGELOG.md) · [Политика безопасности](SECURITY.md)

Всё, что sim обещает, он обещает для каждого открытого в нём файла: **без явного действия ничей текст не теряется** — ни ваш, ни текст другого процесса.

## Установка

Исполняемый файл называется `sim`. Имя пакета — `sim-editor` в AUR и на crates.io и `efg-technologies/tap/sim` в Homebrew; библиотека, на которой он построен, называется `sim-editor-core` и лежит на crates.io.

sim 0.1.0 выпущен. Установить его можно через Homebrew:

```sh
brew install efg-technologies/tap/sim
```

Исходный код релиза лежит на [странице релиза v0.1.0 на GitHub](https://github.com/efg-technologies/sim/releases/tag/v0.1.0) (`sim-0.1.0.tar.gz`). Чтобы собрать из исходников:

```sh
git clone https://github.com/efg-technologies/sim.git
cd sim
cargo install --locked --path sim
```

Пакет `sim-editor` в AUR и крейты `sim-editor` и `sim-editor-core` на crates.io появятся позже.

Затем, если он вам по душе как редактор:

```sh
export EDITOR=sim                     # Ctrl-g в Claude Code, crontab -e, …
git config --global core.editor sim   # git commit (ZZ — зафиксировать, :cq — отменить)
export SUDO_EDITOR='sim --plain'      # sudoedit (в Linux sim и сам работает в режиме plain)
```

Нужен Rust 1.88 или новее. Работает в Linux и macOS в любом терминале; цвета, клавиатурный протокол kitty и OSC 52 используются, если терминал их поддерживает (Ghostty, kitty, WezTerm, tmux). git и ripgrep необязательны: sim использует их, если они есть в `PATH`. Для значков нужен Nerd Font; в Ghostty, kitty и WezTerm они включены с самого начала, в остальных выключены, с однократной подсказкой, а `zi` включает и выключает их. Подробнее — на [странице установки](https://sim.efg-technologies.com/ru/install/).

## Что он умеет

**Показывает скрытое**

- Переопределение направления письма «справа налево», пробел нулевой ширины или управляющий символ отображается как `<U+202E>` или `^[` на пурпурном блоке — в любом состоянии ячейки — и никогда не отправляется в терминал как есть. Буквальный текст `<U+202E>` в файле блока не получает.
- Пробелы в конце строки отображаются как `·`, неразрывный пробел — как `⍽`, табуляция — как `»`.
- Когда другой процесс перезаписывает открытый файл, изменённые строки на мгновение вспыхивают и затем отмечаются в тексте, окошко сообщает, сколько изменений лежит на диске, на вкладке появляется `↯`, а дерево файлов отмечает этот файл. `]c` и `[c` переходят к следующей и предыдущей отметке.
- Изменения относительно git HEAD видны как знаки на боковом поле, буква статуса у каждого файла в дереве (у папки — буква самого сильного статуса среди вложенных) и `+n ~n -n` в строке состояния.
- git не запускается там, где собственная конфигурация репозитория способна запустить команду (`core.fsmonitor`, драйвер фильтра и не только): окошко пишет `git not run` на блоке тревоги, а строка состояния называет ключ и файл. Там, где git запускается, но собственные настройки репозитория (`core.fsmonitor`, путь к хукам, фильтры, внешний diff) отключены, окошко сообщает, сколько их (`2 git settings off`).
- Ссылка Markdown, чей текст называет адрес, которым её цель не является (`[https://good.example](https://evil.example)`, а также ссылка-ссылка `[good.example][1]`, определение которой ведёт в другое место, ссылка на нескольких строках или с обратной косой чертой или сущностью в цели, ссылка HTML `<a href="…">`), показывает цель, а у ссылки по определению ещё и текст, на пурпурном блоке — в режиме чтения и в calm тоже; режим чтения никогда не прячет скобки и URL ссылки.

**Отказывает там, где нужно, и бережёт ваш текст**

- Настройки и команды никогда не читаются из содержимого файлов: никаких строк режима (modeline), файлов конфигурации, плагинов и сети.
- Сохранение атомарное (временный файл, fsync, переименование, fsync каталога) и сначала проверяет хеш файла: если файл на диске изменился, ничего не перезаписывается. Если при сохранении обнаружен конфликт, `:w!` оставляет вашу версию, скопировав чужую в каталог состояния, а `:e!` берёт чужую после снимка вашей.
- Несохранённые изменения сохраняются снимками каждую секунду; после сбоя, `kill -9` или закрытия терминала при повторном открытии файла sim предлагает вернуть их одним шагом отмены.
- Поиск сам находит ripgrep, запускает его с пустым окружением и `--no-config` и никогда не переходит по символической ссылке за пределы проекта.
- `sim --plain` — это одно лишь ядро: один файл, без панели и без внешних программ (ни git, ни ripgrep, ни фильтра, ни хука). Это режим по умолчанию от root и в роли редактора sudoedit.

**Доступность, скорость и чтение**

- Дерево файлов, которое никогда не прыгает, `Ctrl-p` для поиска файлов, `Ctrl-f` для поиска текста с предпросмотром, вероятные файлы отмечены `•`, несколько файлов с панелью вкладок.
- В собственном бенчмарке проекта обработка клавиши занимает менее 1 мс на p99 (файл на 100 000 строк, релизная сборка); первый кадр в репозитории со 100 000 файлов измерен в 1,8–8,7 мс.
- Цвета синтаксиса из палитры вашего терминала, Markdown читается на месте (разметка скрыта, таблицы выровнены, а строка с курсором всегда показана как в файле), три оформления (`zl`), японский перенос по правилам кинсоку и клавиши полной ширины.
- Заголовок редактора — «хлебные крошки», `src › sim.rs › leader_key`: путь и заголовок или функция, в которых находится курсор. Каждый факт показан в одном месте: в строке состояния — режим, ветка, счётчики и позиция, а `CRLF`, `BOM` или файл не в UTF-8 она называет, только если это так; вкладка показывает файл и `●`, полоса прокрутки — позицию, а дерево не в тумане.
- `NO_COLOR` и терминалы менее чем с 8 цветами рисуют только жирностью, подчёркиванием и инверсией, а смысл никогда не зависит только от цвета: изменённая строка — это `┆`, у папок есть буквы статуса, вкладка показывает `↯` для файла, изменённого на диске, а ползунок полосы прокрутки — это рельса `║`, а не инвертированный блок.

**Клавиши, которые можно найти**

- `Space` — клавиша-лидер. Пауза на префиксе (`Space`, `g`, `z`, `Z`, `[`, `]` или оператор вроде `d`) открывает небольшое окно which-key, в котором перечислены клавиши, которые могут идти дальше; если продолжать набирать клавиши, всё работает точно так же, как без окна.
- `:help` и `F1` открывают список всех клавиш и команд с поиском и с описанием того, что делает каждая; `:help tab` находит `Tab`, `Shift-Tab` и `<Space>bp`.
- `:tutor` открывает около пятнадцати минут коротких уроков в одноразовой копии (ничего не записывается), с упражнениями, которые сами отмечаются ✓, когда выполнены верно; он говорит на вашем языке (`LC_ALL`, `LC_MESSAGES`, `LANG`) — на любом из десяти языков этого README.
- `<Space>bp` ставит букву на каждую вкладку, и нажатие буквы переходит к файлу этой вкладки; `<Space>bc` делает то же, чтобы закрыть вкладку (файл с изменениями остаётся открытым, как и при `:q`). Подсказка называет `Tab` и `Shift-Tab` при первом открытии второго файла и показывается, пока вы не воспользуетесь ими три раза.
- Пока совпадения поиска подсвечены, строка состояния показывает, на каком из них вы стоите и сколько их всего, `[3/12]`.
- `sim --help` выводит справку по использованию и переменные окружения, которые читает sim (`NO_COLOR`, `SIM_ON_NORMAL`, `XDG_STATE_HOME`); `sim --version` выводит версию. Ни та, ни другая команда не трогает терминал.

| `<Space>` | лидер |

Всё остальное — vi: перемещения, операторы, текстовые объекты, счётчики, `.`, визуальный режим, `:s`, диапазоны. `Y` копирует до конца строки, `U` повторяет отменённое, а всё скопированное без имени регистра также уходит в системный буфер обмена через OSC 52, в том числе через tmux (`"ay` с именем остаётся внутри sim). Повторно открытый файл открывается на том месте, где вы его оставили. При включённом IME клавиши полной ширины работают как команды; `SIM_ON_NORMAL='fcitx5-remote -c'` выключает IME каждый раз, когда вы возвращаетесь в нормальный режим (`SI_ON_NORMAL`, прежнее имя, по-прежнему работает). Все клавиши собраны в одной таблице, `sim/keys.tsv`: её читают `:help` и which-key, а тесты сверяют её с тем, что делают клавиши. Полный список — на [странице документации](https://sim.efg-technologies.com/ru/docs/).

## Модель безопасности

Вы открываете файлы и репозитории, которые не писали. Атакующий управляет их содержимым, но не вашим компьютером. sim старается сделать так, чтобы это содержимое не могло спрятаться от вас, не могло перенастроить редактор и не могло заставить редактор выполнить код. Он **не песочница**: он работает с вашими правами, не обнаруживает похожие буквы из других систем письма, а его утверждения основаны на собственной спецификации и тестах проекта, а не на независимом аудите. Языковые серверы пока не реализованы; клиент в песочнице запланирован. Чтобы сообщить об уязвимости, прочитайте [политику безопасности](SECURITY.md).

Полная модель угроз, угроза за угрозой, изложена на [странице безопасности](https://sim.efg-technologies.com/ru/security/). Подробнее — в трёх больших статьях: [скрытые и двунаправленные символы](https://sim.efg-technologies.com/blog/hidden-characters/), [репозитории, запускающие код](https://sim.efg-technologies.com/blog/repositories-that-run-code/) и [безопасное сохранение и секреты](https://sim.efg-technologies.com/blog/safe-saves/).

## Сравнение с Vim, Neovim и Helix

Vim, Neovim и Helix — зрелые редакторы, а sim — новый. Сравнивается только то, что сказано в первоисточнике; [страница сравнения](https://sim.efg-technologies.com/ru/compare/) приводит все ссылки (проверено 2026-10-17: Vim 9.2.1202, Neovim 0.12.6, Helix 25.07.1).

| | Vim | Neovim | Helix | sim |
|---|---|---|---|---|
| Расширения | Vim script, пакеты | Lua, Vim script | в релизах системы плагинов нет; PR про Steel [#8675](https://github.com/helix-editor/helix/pull/8675) — черновик | нет, намеренно |
| Строки режима | включены (для root выключены); `'modelinestrict'` с [9.2.0350](https://github.com/vim/vim/commit/4c2879471) | включены (для root выключены) | не разбираются ([#729](https://github.com/helix-editor/helix/issues/729)) | никогда не читаются |
| Конфигурация внутри проекта | `'exrc'`, по умолчанию выключен | `'exrc'`, список доверенных | `.helix/config.toml` загружается в 25.07.1; доверие к рабочей области — в ветке разработки | её нет |
| U+202E и родственные | `<202e>` | `<202e>` | нет отметки в 25.07.1 (наш тест; [#11255](https://github.com/helix-editor/helix/issues/11255)) | `<U+202E>` на пурпурном блоке |

Что другие пока делают лучше: в Neovim и Helix есть клиент языкового сервера, в Vim и Neovim — плагины и макросы. В sim пока нет ничего из этого.

## Участие в разработке

sim — одна программа из двух крейтов: **ядро** (`sim-editor-core`, в `core/`: буфер, грамматика vi, сохранение, слияние с тем, что пишут другие процессы, терминал) и **редактор** (`sim-editor`, в `sim/`: исполняемый файл `sim` с деревом файлов, поиском файлов, поиском текста, метками, синтаксисом, оформлениями и мышью). Обоснование каждого выбора — в [CONCEPT.md](CONCEPT.md) вместе с исследованиями, на которых оно основано. Что sim должен делать — в [SPEC.md](SPEC.md): у каждого требования есть ID, а у каждого ID есть тесты.

Пирамида: [CONCEPT](CONCEPT.md) (почему) → [SPEC](SPEC.md) (что, с ID) → `core/src` и `sim/src` (как) → тесты (доказательство). Изменения идут вниз, доказательство — вверх. Правила собраны в [CLAUDE.md](CLAUDE.md).

```sh
sh scripts/check.sh          # fmt, clippy, тесты, трассировка SPEC↔тесты, оба ограничения на число строк, зависимости ядра, размер бинарного файла
sh scripts/e2e.sh            # ядро (как `sim --plain`) и редактор в tmux (свой сокет)
cargo test --release --workspace -- --ignored bench   # требования к производительности
```

Тесты свойств, фаззеры с моделью «без потерь» для текста каждой стороны, внесение сбоев на каждом шаге сохранения, дифференциальный оракул на основе nvim и эталонные снимки отрисованного экрана следят за тем, чтобы обещания выполнялись.
