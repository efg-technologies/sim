# Changelog

All notable changes to sim are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- The bar says `colors stopped` among its state words, for as long as it is so, for a file whose parse the highlighter gave up after 5 s (it was said once on the status line, where a key ended it) (SYN-3).
- The changes view: `<Space>ge` opens the panel with only the files that differ from `HEAD`, staged and unstaged together and untracked ones too, in their folders. Each file shows its status letter and `+n −n` from `git diff --numstat HEAD` (an untracked file its line count) and each folder the sums. Deleted files are listed, and Enter opens `HEAD`'s version of one read-only, as a buffer named `HEAD:path` whose tab says so; a rename is one row, `old → new`, with a cut that keeps the new name whole and marks every cut with `…`. `<Space>ge` again, or `q`, goes back to the tree. In `sim --plain` the key is refused, naming plain mode (DIFF-1 to DIFF-6).
- The editor's title is a breadcrumb, `src › sim.rs › leader_key`: the file's path below the root and the section the cursor is in, the nearest Markdown heading or the function, `impl`, class, struct, trait or module it is inside (found by a few string tests over the lines above it, not a parse). In depth it is the title of the editor's box, in flat it is at the right of the tab bar, and long ones are cut from the left with `…` (UI-18).
- The Markdown read view: in a Markdown file every line but the cursor's (and, in Visual mode, the selected ones) is drawn as it reads, in place and in the one pane: the markers of emphasis (`**`, `*`, `_`) and of inline code are not drawn, and tables are aligned by display width (a Japanese cell counts two columns a char, `:--`, `:-:` and `--:` align the text, the delimiter row is `├─┼─┤`). Only those markers are ever hidden, never a `#`, a bracket, a URL or a char of text, and a char shown in another form (`^[`, `<U+202E>`) is still the alert's block wherever it is: in a span, a link, a URL, a cell or code (MD-2). A table that does not fit the pane, or has a cell too many, stays raw, whole. `<Space>um` turns the read view off and on, the choice is remembered in the state directory and the first run is on; `sim --plain` has none; a click in a read line puts the cursor on the char of the file under the pointer; and the window draws it too (MD-1 to MD-9)
- `sim-gui`, a window for sim, in `gui/` (a third workspace member, `publish = false`: it is not on crates.io, Homebrew or the AUR yet, and the `sim` binary and the `sim-editor` and `sim-editor-core` crates do not depend on it). It draws the depth look on the GPU (boxes raised from a floor with soft shadows, a chip for the shown tab, a window that floats over a dimmed page, a char shown in another form as a rounded pill) from the editor's own screen: the keys, the modes, the colors and the jobs are sim's, and the window keeps no rule of its own (GUI-1 to GUI-17). It is built with `cargo run -p sim-gui -- <file>`; the text is set in the first common coding font the system has (JetBrains Mono, Fira Code, Cascadia Mono, Source Code Pro, Noto Sans Mono, DejaVu Sans Mono, Liberation Mono, Menlo, Monaco, then the system's monospace; `SIM_GUI_FONT` names another, `sim-gui --help` lists everything it reads from the environment), the input method works where a key is text, and `SIM_GUI_REDUCED_MOTION` turns the motion off. It starts through the same function as the terminal, so it is plain as root and as the editor of `sudoedit` (PLAIN-1: no git, no ripgrep, no filter, no hook), and a hangup or a termination snapshots what is unsaved as in the terminal. Its dependency list is closed and has no webview and nothing that speaks to a network. Not seen on a real display yet.
- The frame says what the guard did to a repository: where git is not run for the repository's config the tree's box says `git not run` in the alert's block (in flat, the tree's header does) and the lines of both boxes are the alert's, and where git runs with settings of the repository's own turned off (the monitor, the hooks path, an external diff, a text conversion, a filter) it says `n git settings off`; a narrow panel gets a shorter form. The status line names the first setting once, and `<Space>gi` says again why git was not run or which settings were turned off (GIT-5).
- The lines another process has just written into the open file are lit for 400 ms, the whole text of each in the change's green as a solid block, bold (bold on inverse with no color), and are then marked as they were (UI-19). The core lists the lines a merge marked (`App::wrote`, one field).
- A Markdown link whose text looks like an address that its target is not (`[https://good.example](https://evil.example)`, a host that differs, a path that differs from a target with no host, or a `javascript:`, `data:` or `vbscript:` target) has its target drawn on the alert's block in the raw line and in the read view, which hides no bracket, text or URL of a link (MD-10).
- `:tutor`: about fifteen minutes of short lessons in a scratch buffer, in the language of `LC_ALL`, `LC_MESSAGES` or `LANG` (English, 日本語, 简体中文, 繁體中文, 한국어, Español, Português, Français, Deutsch, Русский; English for any other), with exercises that are graded as you type: a row `[ ] 1.1 …` shows `✗` and shows `✓` as soon as the lines under it are right (and `✗` again if you undo). Nine lessons in the editor (movement, typing, deleting and changing, undo, copy and paste, searching, saving and quitting, what sim shows that other editors hide, and the finder, the tree, the looks and `<Space>bk`, whose exercises are marked done when you do them) and eight with `--plain`. Nothing typed there writes a file or a snapshot: `:w` says the tutor is a scratch copy, and `:q!` leaves it (TUTOR-1 to TUTOR-4).
- Markdown callouts (GitHub's alerts): `> [!NOTE]`, `[!TIP]`, `[!IMPORTANT]`, `[!WARNING]` and `[!CAUTION]`, in any case, on a quote's first line with a body after it, are drawn in the read view as the kind's word (`Note`) in bold, with GitHub's octicon before it where `zi` has the icons on; no kind has a hue (the word, always, and the icon tell it; in flat and depth the bar is the primary gray where a plain quote's is the secondary; calm and `NO_COLOR` have the word in bold), and the line the cursor is on shows `[!NOTE]` as typed, in bold. Which quotes are callouts was measured against GitHub's renderer (24 forms in a test); other `[!KIND]`s stay quotes (MD-11).
- Calm lights a yank too, for the same 150 ms: the text it took is in the gray of a Visual selection (lightness alone, |Lc| >= 15 against the page, SYN-5), and underlined where the selection is (no truecolor, `NO_COLOR`). It showed nothing; the flash in flat and depth is as it was (UI-13).
- `<Space>bk` says again where the version that `:w!` or `:e!` gave up was copied, alone on the status line (a path wider than the line is cut from the left, so the file's name stays), as `<Space>gi` does for the guard (SAFE-7).

### Changed

- sim's git is built in one function, and what a command line can stop is neutralized instead of making sim skip the repository: a file system monitor, hooks (`core.hooksPath` points to an empty private directory), a filter (emptied by name, except git-lfs's own filter as `git lfs install` writes it, with only git-lfs's harmless settings beside it), an external diff and a text conversion run nothing, and git answers. A repository whose config still could run a command that nothing stops, such as `core.sshCommand` or an `include`, is skipped as before, with the key named (GIT-1 to GIT-3).
- The status line says each fact once. The file's name, which the tab and the breadcrumb say, and `Top`, `Bot` and `NN%`, which the scrollbar shows, are gone from it (they stay where there is no tab bar or no scrollbar); `utf-8` and `LF` are said only when they are not so: `not utf-8`, `CRLF` and `BOM` show at its right when they apply, and the file type only for a script whose name does not tell it (`#!/usr/bin/env python3`). The core's own line, which `sim --plain` shows, says `CRLF` and `BOM` among its words too (UI-10, VIS-9).
- The tree is not in fog: its rows no longer fade by their distance from the open file or the cursor. Only the rows that are no match of a `/` search fade (LOOK-7).
- Markdown is no longer drawn with every marker on the screen by default: the first run is the read view (`<Space>um` shows the raw text, and the line the cursor is on is always the file's own text). UI-8's looks are what the raw lines and `--plain` show.
- A submodule is one entry with its status and no child git runs in it: `git status` sees its commit and not its work tree, and every diff of sim's takes no submodule (GIT-4).
- Without color the scrollbar's handle is a `║` rail at the weight of the text and no longer an inverse block, the brightest thing on the screen even when the file fits (UI-11, COLOR-3). The colors of the handle are as they were.
- The paints of a yank's flash, a search's matches and a write from outside come before the tint and the words of a changed row, as UI-13 and UI-14 say (they came after, and a changed row hid them).

### Fixed

- The highlighter no longer spins on a core for ever on JavaScript in a Markdown fence, in an HTML `<script>` and in the other syntaxes that embed it (a statement without a semicolon that ends in a block comment, a JSDoc comment after `return start`): syntect's parser went round in a circle on matches that consume nothing, and now goes on one char after 128 of them (a copy of syntect 5.3.0 with that guard is in `vendor/`, SYN-3). A parse that is only slow is still given up after 5 s.
- The mark of a link that lies (MD-10) no longer judges a path in the text against a target that has a host: `[/r/rust](https://www.reddit.com/r/rust)` and `` [`/dev/urandom`][14] `` were 46 of the 128 marks in 6,000 real files and all honest, and the browser shows the host. A path whose first segment is a host (`[/good.com/login](https://evil.com/login)`) is read as that host and is still marked.
- sim died with a panic when it opened a file whose name starts with digits that read as a line number (`h264.rs`, `e1000.c`) and when `123` was typed after a `:` or `/` in a file with fewer lines, once the interface was drawn: the status line and the command line were read as numbered lines of the text (UI-6).
- The message after `:w!` or `:e!` ended in the copy's absolute path, which a long state directory or a macOS `$TMPDIR` pushed off the line: it is now told as a shell takes it, `~/.local/state/sim/a.rs.1.disk` below the home directory, and `<Space>bk` says it again (SAFE-7).
- The breadcrumb in flat's tab bar was drawn as it was given, so a directory named with an escape sequence, or a Markdown heading with one, could reach the terminal (SAFE-8). The parts are now made fit to be drawn like every other row text (U+FFFD for a control, bidirectional or zero-width char) and both places that draw them draw what `fit` gives (UI-18).
- With the cursor on a Markdown fence line the breadcrumb could name the wrong heading for a frame; the line above now says which fence it is (UI-18).
- The status line said a non-UTF-8 file's encoding twice (`read-only: not valid UTF-8` in the middle and `not utf-8` at the right); the middle says `read-only` and the right the format (UI-10).
- `sim --plain` no longer shows the icons hint (`zi: icons (needs a Nerd Font)`) or uses up its one-time marker: `zi` is refused in plain mode, and the editor's first run after plain ones still gives the hint once (ICON-1, PLAIN-1).
- The mark of a link that lies (MD-10) could be got around by the form of the link. The target is now read as a browser reads a URL: a `\` ends the authority (`https://evil.com\@good.com/` goes to evil.com), `https:evil.com` and `https:/\evil.com` too, tab and newline are dropped, and an authority with a `%`, a control char, a blank, an entity or a char that is not ASCII is never taken for another host. The text is found with its brackets nested and escaped (`[good.com [x]](…)`) and judged word by word after its escapes and entities are decoded (`[Visit good.com](…)`, `good&#46;com`); a `<…>` target with blanks, blanks after the `(`, and a link that goes over lines are judged whole. Reference links are judged by their definitions (`[good.com][1]` with `[1]: https://evil.com`: the target is marked on the definition and the text on the use), any two letters are a country code unless they end the name of a source file (`paypal.com.mx`), and calm marks the link too, as it marks a hidden char.
- The mark of a link that lies (MD-10) was reviewed again, and a differential fuzz against two renderers (markdown-it and md4c, about 130,000 generated documents) and 6,000 Markdown files of one machine were looked at for what got by and what cried wolf. A line made of brackets could freeze sim for minutes (a walk that was quadratic in the line); the work is now linear and bounded for a line, a frame and a document, and what is past a bound is marked and not trusted. A definition in a block quote or a list item (`> - > [1]: …`), a reference whose text goes over lines or is written with escapes, entities or emphasis, an image in the text of a reference, and a use that no definition resolves where one may have been missed are judged or marked. A link written in raw HTML (`<a href="…">`) is judged like the rest, with the tags that a browser reads and CommonMark does not. Code is judged like the rest: a stray backtick, or a fence that a renderer does not open, made a live link look like code to the highlighter. A bracket in a comment, a tag, an autolink or a code span no longer pairs with the wrong one, an escaped `\!` is no image, the `\` of a target is read as the `%5C` that a renderer writes, a word after a label (`site:good.com`, `url=good.com`) or a full stop of another script (`good。com`) is an address, and strikethrough, a processing instruction, CDATA and a mark of direction no longer hide one. What it no longer marks, because the real files showed it was no lie: a badge (an image in a link), a raw-HTML link around an image, the definitions of a long CHANGELOG, an array or a shell test in code, a version (`HTTP/1.1`), `~30`, a name with underscores, a dot directory, an emoji and a full stop, a subdomain of the host in the text, and Japanese labels. A file is Markdown for this by the highlighter's own table of names (`.md`, `.mdown`, `.markdown`, `.markdn`), and a line that the highlighter gives a link is looked at in any file.
- The mark of a link that lies (MD-10) no longer passes a target that has a scheme as a relative path (`search-ms:` opens a share of the host in the text, `tel:`, `ms-msdt:`, `https:evil.com`): only a target with no scheme is relative, a scheme that is not special and has no `//` goes to no host a text can name, and `mailto:` is judged by the host of each recipient, `to`, `cc` and `bcc`. A subdomain is trusted only when the host in the text is not a suffix that many share (`[github.io](https://evil.github.io)`, `co.uk`, `amazonaws.com`), and a host with letters that are not ASCII (a Cyrillic `о`, `ｇｏｏｇｌｅ．ｃｏｍ`, `google.cоm`) is an address that is judged, honest only as the same string or as its punycode. SPEC has a table of the forms of a URL and of a host.

## [0.1.0] - 2026-10-17

First public release: sim, the next-generation Vim. It shows even what is hidden, it is secure, and it is written in Rust. One program, `sim`, in two crates: the core (`sim-editor-core`, library `sim_core`) and the editor (`sim-editor`, the binary).

### Added

#### Safety: nobody's text is lost without an explicit action (SAFE)

- Atomic saves: a temporary file in the same directory (mode 0600, `O_EXCL`), written, fsynced, renamed over the file, and the directory fsynced; whichever step fails, the old or the new version stays intact (SAFE-1). A file owned by someone else, with hard links, or in a directory that is not writable is saved in place, after a recovery copy has been written and synced (SAFE-2).
- Compare-and-swap saves: right before saving, the file on disk is compared with what was read; if it changed, nothing is written over it (SAFE-5).
- Opening and saving without editing gives byte-identical output: line endings, final newline, BOM and permissions (SAFE-3). A file that is not valid UTF-8, or has a NUL in its first 8 KB, opens read-only and says why (SAFE-4).
- Unsaved changes are snapshotted at most once per second into a private state directory (`$XDG_STATE_HOME/sim`, else `~/.local/state/sim`, mode 0700). After a crash, `kill -9` or a closed terminal, reopening the file offers them back as one undo step (SAFE-6, STATE-1). SIGTERM and SIGHUP snapshot and exit; every way out, a panic included, restores the terminal (CLI-4).
- Hidden characters are shown, never sent raw to the terminal: control characters as `^[`, bidirectional controls, U+200B and a stray U+FEFF as `<U+202E>`, drawn in the alert's block in every state a cell can be in (SAFE-8, UI-15).
- No modelines: settings and commands are never read from file contents. No network access: no source file of sim uses `std::net`, and the core depends on an allowlist of crates that `scripts/check.sh` enforces (SAFE-9).
- A file's name is a path for git, never a pattern (`GIT_LITERAL_PATHSPECS`), and the sign column's diff never enters a submodule (`--ignore-submodules=all`, `diff.submodule=short`): a file named `*` or `:(top)` in a repository whose submodule has config of its own could make git run that submodule's external diff (MARK-1, UI-5).

#### Changes from outside are merged and marked (DISK)

- The directory of the open file is watched, and a change on disk is taken in within 100 ms, saves by rename, deletion and re-creation included. Events from sim's own saves are recognized by hash and ignored (DISK-1).
- A clean buffer is reloaded and what changed is marked. A dirty buffer gets a three-way merge of base, yours and the disk's (our own, built from two line diffs, with no conflict-marker strings): what does not conflict is taken in and marked, word by word, until you have looked at it (DISK-2, DISK-3, DISK-4).
- A conflict is never merged away: your text stays, marked, and the file on disk is not written over. `:w!` keeps yours and `:e!` takes the disk's, and each copies the version it gives up into the state directory first (SAFE-7).
- `]c` and `[c` go to the next and the previous mark; a mark stays until the cursor enters its line; `:seen` clears them all (DISK-6).
- Filters: `:{range}!cmd` and `!` in Visual mode run asynchronously with `sh -c`, can be cancelled with Ctrl-c, and replace their lines as one undo step; a failing filter changes nothing and shows its stderr (FILT-1, FILT-2).

#### Keys: the vi grammar, minus vi's accidents (VI, CLI)

- Motions, operators, text objects, counts, `.`, Visual mode (`v V o`), `:s` and ranges; `/ ? n N * #` with smartcase and incremental search, in the syntax of `regex-lite` (VI-1 to VI-7, VI-14).
- `Y` yanks to the end of the line, `U` redoes, Ctrl-s saves in every mode, `ZZ` saves and quits, `ZQ` quits discarding, `q` quits, `:cq` exits with 1 to abort a git commit; the arrows, Home, End, PageUp, PageDown and Delete work in every mode (VI-13, VI-12, CLI-3).
- One register without names. Every yank also reaches the system clipboard through OSC 52, also through tmux (VI-8).
- The kitty keyboard protocol is enabled when offered, Esc has no delay, and a bracketed paste is one undo unit (VI-9).
- With the IME on, full-width ASCII is read as half-width in Normal mode; `SIM_ON_NORMAL` runs a command (for example `fcitx5-remote -c`) each time Normal mode is entered (VI-10, VI-11).
- Reopening a file puts the cursor where you left it (the last 1,000 files; not for `+cmd`, `file:line` or git's message files) (CLI-6).
- `sim`, `sim dir`, `sim file`, `sim file:42[:col]`, `sim +N file`, `sim +/re file`, `sim +cmd file`; `--` ends the options (CLI-1, CLI-2).

#### The project at your fingertips (the editor)

- A tree of the project on the left (`sim`, `sim dir`): directories first, then files by name, numbers compared as numbers, never reordered; read in the background; Ctrl-n opens, focuses and closes it (TREE-1 to TREE-5).
- Several files open at once, each a complete core editor with its own undo, snapshots, watcher and saves; Tab and Shift-Tab switch; `:wa`, `:qa` and `:qa!` act on all of them (BUF-1 to BUF-3).
- Finding a file: `/` in the tree lights up fuzzy matches and the folders leading to them in place, without moving anything; Ctrl-p anywhere opens a picker with the matches and a preview (FIND-1 to FIND-4).
- Searching contents: Ctrl-f anywhere searches the files as you type (literal, smartcase, `.gitignore` respected), using ripgrep when it is on `PATH`; results are grouped by file with a preview; Enter opens there, Esc puts everything back. A search never writes, never follows a symlink out of the root, and never runs code a repository controls, such as ripgrep's config or `--pre` (GREP-1 to GREP-8, PICK-1 to PICK-5).
- Marks: files git reports as changed, and files that changed on disk while sim runs, carry the change color, and folders carry the letter of the strongest status below them. The five files you are most likely to open next, ranked from your own history, carry `•`. `.` in the tree narrows it to what changed, is open or was opened recently (MARK-1 to MARK-3).
- Syntax highlighting for the languages of bat's syntax set, in the terminal's own palette; `zh` turns it on and off; it never delays a key (SYN-1 to SYN-5).
- The mouse: click to open or place the cursor, wheel to scroll, drag to select. It never edits by itself (PTR-1, PTR-2).

#### Readable by measurement, meaning without color (LOOK, UI, COLOR, ICON, VIS)

- Three looks, cycled with `zl` and remembered: calm (one change color), flat (green for what comes, red for what goes, with a tint behind every row of a change) and depth (the default: boxes, an overview ruler, and text that fades with its distance from the cursor) (LOOK-1 to LOOK-4, LOOK-6 to LOOK-9).
- Colors computed from the terminal's background with APCA: text at Lc 90, secondary text at Lc 60, and text on every surface at Lc 75 or more on the eight reference backgrounds of SPEC. The calm look's change color stays distinguishable under protan, deutan and tritan color vision (VIS-4, VIS-5, UI-12, LOOK-9).
- The interface of the editor: a header and icons in the tree, git status per entry, a tab bar, a sign column for changes against `HEAD`, indent guides and whitespace marks, `TODO`/`NOTE`/`FIXME` badges, Markdown drawn with every character still on screen, a status line with the security state, a scrollbar, a flash on yank, and lit matches of the last search (`:noh` clears them) (UI-1 to UI-14).
- One hue, one meaning across the interface: grays and weight are structure, green, amber and red are changes, blue is where you act, cyan is a heading, magenta is only what is hidden or dangerous (COLOR-1).
- With `NO_COLOR` set, or on a terminal that cannot do 8 colors, sim writes no color and asks the terminal for none: weight, underline and inverse video say what the colors said, and a changed, an added and a deleted line are three shapes in the sign column (COLOR-2, COLOR-3).
- Icons need a Nerd Font, which a terminal does not announce: they start on in Ghostty, kitty and WezTerm and off elsewhere, with a one-time hint to turn them on with `zi` (ICON-1).
- Prose (`.md`, `.txt`, `COMMIT_EDITMSG` and files without an extension) wraps at 72 columns in the core and at the pane's width in the editor, with Japanese kinsoku; a tab is 4 columns; the cursor line is kept in the middle of the screen after a jump (VIS-6 to VIS-8, VIS-12, UI-9).

#### Plain mode and `$EDITOR`

- `sim --plain` is the core alone: the calm look, one file, no panel, and no program of its own run (no git, ripgrep, filter or hook). It is the default for root and when sim is the editor of `sudoedit` (on Linux; `SUDO_EDITOR='sim --plain'` says it anywhere) (PLAIN-1).
- Meant to be `$EDITOR`: `git commit` works end to end with `ZZ` to commit and `:cq` to abort (CLI-3). `sim --plain` without a file shows a short intro until the first key (CLI-5).
- sim reads the old name `SI_ON_NORMAL` and copies the state directory of `si`, the minimal editor it grew from, once, without touching the old one (VI-11, STATE-1).

#### Performance requirements

- SPEC sets them and the repository checks them with benchmarks (`cargo test --release --workspace -- --ignored bench`): `sim --plain +q` on a 10,000-line file within 5 ms; a key within 1 ms at p99 on a 100,000-line file, also with the panel open and highlighting on; a first frame within 20 ms in a repository of 100,000 files; a release binary of at most 5 MB (PERF-1 to PERF-5, SPEED-1, SPEED-2).

#### Keys you can find (KEY, CLI)

- One key table, `sim/keys.tsv`, is the only source of which-key and `:help` (and of the README's table of keys). A test feeds every key to a sim and fails for a key that does something and is not in the table, and for an entry that does nothing (KEY-1).
- `Space` is a leader key in Normal mode and in the tree: `<Space> b p` and `<Space> b c` run from it. Space followed by a key no sequence has does nothing, Esc ends the sequence, and where Space is text (Insert mode, the command line, the query of the tree or of the picker) it is the character (KEY-2).
- A pause of 200 ms on a prefix (`Space` and what follows it, `g`, `z`, `Z`, `[`, `]`, and an operator with what follows it, in Normal and Visual mode and in the tree) opens which-key: a small window near the bottom of the screen that lists the next keys, one line each, from the key table. Typing on is exactly what it is without the window, Esc closes it, and the terminal's cursor stays at the cursor of the text (KEY-3).
- `:help` and `F1` open the picker as `Help · keys and commands`: one row for each entry of the key table, fuzzy-filtered as the finder filters paths, with a preview of the longer text. Enter and Esc close it and it runs nothing; `:help {words}` opens it with the words typed, and `tab` finds `Tab`, `Shift-Tab` and `<Space>bp`. Keys are written as people write them, with no escape of the table (`<` for `<lt>`, alternatives as `h / <Left>`) (KEY-4).
- `<Space> b p` puts a letter on each tab and the letter jumps to its file; `<Space> b c` does the same to close one. A modified file is not closed: it follows `:q` (KEY-5).
- The first time a second file is open, the message line says `Tab / S-Tab: next / previous file`, once for the session, until Tab or Shift-Tab has been used three times (KEY-6).
- While the matches of a search are lit, the status line says which one the cursor is at and how many there are, `[3/12]` (UI-17).
- The boxes' titles say what the box is, with no number: the panel's says `files`, the editor's says nothing, since the file's name is in its tab (UI-16).
- `sim --version` prints `sim 0.1.0` and exits 0. `sim --help` prints the usage, with the environment sim reads (`NO_COLOR`, `SIM_ON_NORMAL`, `XDG_STATE_HOME`), and exits 0. Any other argument that starts with `-` (and is not `--plain` or `--`) prints the same usage to stderr and exits 2. None of them touches the terminal (CLI-7, CLI-1).
