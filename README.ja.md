# sim ― 新時代の Vim

**sim**(*sim editor* とも呼びます。*Secure vIM* の略)は、Rust でゼロから書いた新時代の Vim です。モーダル編集と Vim の基本のキーを受け継いでいます。モードラインは読まず、プラグインは読み込まず、ネットワークにもつながりません。そのうえで、ふだんは見えないもの(不可視文字、エディタの外からの書き込み、コードを実行しうるリポジトリ)を画面に出します。

**プラグインなし。モードラインなし。ネットワークなし。**

ウェブサイト: <https://sim.efg-technologies.com/ja/> ・ Linux と macOS ・ MIT OR Apache-2.0 ・ [変更履歴](CHANGELOG.md) ・ [セキュリティポリシー](SECURITY.md)

sim が約束することは、開いているどのファイルにも当てはまります。**明示的な操作がないかぎり、誰のテキストも失われません**。あなたのものも、ほかのプロセスのものも。

## インストール

バイナリ名は `sim` です。パッケージ名は、AUR と crates.io では `sim-editor`、Homebrew では `efg-technologies/tap/sim` です。土台になるライブラリは crates.io の `sim-editor-core` です。どれも予定で、**まだ公開していません**。いまはソースからビルドしてください。

```sh
git clone https://github.com/efg-technologies/sim.git
cd sim
cargo install --locked --path sim
```

そのうえで、エディタとして使いたければ次のようにします。

```sh
export EDITOR=sim                     # Claude Code の Ctrl-g、crontab -e など
git config --global core.editor sim   # git commit(ZZ でコミット、:cq で中止)
export SUDO_EDITOR='sim --plain'      # sudoedit(Linux では sim が自分で plain になります)
```

Rust 1.88 以降が必要です。Linux と macOS の任意の端末で動き、端末が対応していれば、色、kitty キーボードプロトコル、OSC 52 を使います(Ghostty、kitty、WezTerm、tmux)。git と ripgrep は任意で、`PATH` にあれば sim が使います。アイコンには Nerd Font が必要です。Ghostty、kitty、WezTerm では最初からオン、ほかではオフで、1 度だけ案内が出ます。`zi` でオン・オフを切り替えます。詳しくは[インストールのページ](https://sim.efg-technologies.com/ja/install/)をご覧ください。

## できること

**隠れたものを見せる**

- 右から左への上書き文字、ゼロ幅スペース、制御文字は、セルがどんな状態でも `<U+202E>` や `^[` としてマゼンタのブロックで描かれ、端末にそのまま送られることはありません。ファイルに書かれた文字列 `<U+202E>` にはブロックがつきません。
- 行末の空白は `·`、ノーブレークスペースは `⍽`、タブは `»` で示します。
- 開いているファイルを別のプロセスが書き換えると、変更された行に本文で印がつき、ディスク上にいくつ変更があるかを枠が示し、タブには `↯` が出て、ツリーのそのファイルにも印がつきます。`]c` と `[c` で、次の印・前の印へ移動できます。
- git HEAD との差分は、行の横の記号、ツリーの各ファイルのステータス文字(フォルダには、配下でもっとも強いステータスの文字)、ステータス行の `+n ~n -n` で見えます。
- リポジトリ自身の設定がコマンドを実行しうる場合(`core.fsmonitor`、フィルタドライバなど)、git は実行しません。ステータス行に、原因のキーとファイルが出ます。

**拒むべきものは拒み、テキストは失わない**

- 設定やコマンドをファイルの中身から読むことはありません。モードラインも、設定ファイルも、プラグインも、ネットワークもありません。
- 保存はアトミックです(一時ファイル、fsync、rename、ディレクトリの fsync)。先にファイルのハッシュを比べ、ディスク上で変わっていれば何も上書きしません。保存で衝突が見つかったとき、`:w!` は相手のバージョンをステート用ディレクトリへコピーしてから自分のものを残し、`:e!` は自分のバージョンのスナップショットを取ってから相手のものを取り込みます。
- 未保存の変更は 1 秒おきにスナップショットされ、クラッシュ、`kill -9`、端末を閉じたあとにファイルを開き直すと、1 回の undo として復元を提案します。
- 検索は ripgrep を自分で探し、環境変数を空にして `--no-config` つきで実行し、プロジェクトの外へ出るシンボリックリンクはたどりません。
- `sim --plain` は中核だけの sim です。ファイルは 1 つ、パネルなし、外部プログラムは一切実行しません(git も ripgrep もフィルタもフックも)。root と sudoedit のエディタとしての既定です。

**たどり着く速さ、速度、読みやすさ**

- 動かないプロジェクトツリー、ファイルを探す `Ctrl-p`、プレビューつきでテキストを探す `Ctrl-f`、次に開きそうなファイルの `•`、タブバーによる複数ファイルの編集。
- プロジェクト自身のベンチマークで、1 キーの処理は p99 が 1 ms 未満です(10 万行のファイル、リリースビルド)。10 万ファイルのリポジトリでの最初のフレームは、実測で 1.8〜8.7 ms でした。
- 端末のパレットから作るシンタックスカラー、何も隠さずに描く Markdown、3 つの見た目(`zl`)、日本語の禁則処理と全角キー。
- `NO_COLOR` と 8 色未満の端末では太さ・下線・反転だけで描き、意味を色だけに頼りません。変更行は `┆`、フォルダにはステータス文字、ディスク上で変わったファイルのタブには `↯` が出ます。

**見つけられるキー**

- `Space` がリーダーキーです。プレフィックス(`Space`、`g`、`z`、`Z`、`[`、`]`、`d` のような演算子)で少し待つと、次に押せるキーを並べた小さな which-key のウィンドウが開きます。そのまま打ち続ければ、ウィンドウがないときとまったく同じに動きます。
- `:help` と `F1` で、すべてのキーとコマンドを、それぞれの働きつきで検索できる一覧が開きます。`:help tab` で `Tab`、`Shift-Tab`、`<Space>bp` が見つかります。
- `<Space>bp` で各タブに文字が付き、その文字を押すとそのファイルに移ります。`<Space>bc` は同じ方法でタブを閉じます(変更のあるファイルは、`:q` と同じく開いたままです)。2 つ目のファイルを開いたとき、`Tab` と `Shift-Tab` のヒントを、3 回使うまで表示します。
- 検索の一致が点灯しているあいだ、ステータス行に何番目で全部でいくつかを `[3/12]` の形で表示します。
- `sim --help` は使い方と sim が読む環境変数(`NO_COLOR`、`SIM_ON_NORMAL`、`XDG_STATE_HOME`)を、`sim --version` はバージョンを表示します。どちらも端末には触れません。

## セキュリティモデル

自分で書いていないファイルやリポジトリを開く場面を想定します。攻撃者が握っているのは中身であって、あなたのマシンではありません。sim は、その中身がユーザーから隠れられず、エディタの設定を書き換えられず、エディタにコードを実行させられないようにします。**サンドボックスではありません**。ユーザー自身の権限で動き、ほかの文字体系の似た文字は検出せず、主張の根拠は第三者の監査ではなく、プロジェクト自身の仕様とテストです。言語サーバーはまだありません。サンドボックスつきのクライアントを予定しています。脆弱性を報告するときは、[セキュリティポリシー](SECURITY.md)をお読みください。

脅威モデル全体は、脅威ごとに[セキュリティのページ](https://sim.efg-technologies.com/ja/security/)にまとめています。さらに詳しい長文記事が 3 本あります。[不可視文字と双方向制御文字](https://sim.efg-technologies.com/ja/blog/hidden-characters/)、[リポジトリがエディタ経由でコードを実行する 6 つの入り口](https://sim.efg-technologies.com/ja/blog/repositories-that-run-code/)、[安全な保存と秘密情報](https://sim.efg-technologies.com/ja/blog/safe-saves/)です。

## Vim・Neovim・Helix との比較

Vim、Neovim、Helix は成熟したエディタで、sim は新しいエディタです。比べているのは、一次情報が述べていることだけです。すべての出典は[比較のページ](https://sim.efg-technologies.com/ja/compare/)にあります(2026-10-17 時点の確認。Vim 9.2.1202、Neovim 0.12.6、Helix 25.07.1)。

| | Vim | Neovim | Helix | sim |
|---|---|---|---|---|
| 拡張 | Vim script、パッケージ | Lua、Vim script | リリース版にプラグインの仕組みはない。Steel の PR [#8675](https://github.com/helix-editor/helix/pull/8675) はドラフト | 意図的になし |
| モードライン | オン(root はオフ)。[9.2.0350](https://github.com/vim/vim/commit/4c2879471) 以降は `'modelinestrict'` | オン(root はオフ) | 解釈しない([#729](https://github.com/helix-editor/helix/issues/729)) | 読まない |
| プロジェクト固有の設定 | `'exrc'`、既定でオフ | `'exrc'`、信頼リスト | 25.07.1 は `.helix/config.toml` を読み込む。信頼は開発ブランチ | そもそもない |
| U+202E など | `<202e>` | `<202e>` | 25.07.1 では印がない(私たちの検証。[#11255](https://github.com/helix-editor/helix/issues/11255)) | マゼンタのブロックの `<U+202E>` |

他のエディタが、まだ優れている点: Neovim と Helix には言語サーバーのクライアントがあり、Vim と Neovim にはプラグインとマクロがあります。sim には、どれもまだありません。

## 開発に参加する

sim は 2 つのクレートからなる 1 つのプログラムです。**中核**(`sim-editor-core`、`core/`: バッファ、vi の文法、保存、ほかのプロセスの書き込みとのマージ、端末)と、**エディタ**(`sim-editor`、`sim/`: バイナリ `sim`。ツリー、検索、印、シンタックス、見た目、マウス)です。それぞれの選択の理由は、根拠となった調査とともに [CONCEPT.md](CONCEPT.md) にあります。sim が満たすべきことは [SPEC.md](SPEC.md) にあり、すべての要件に ID があり、すべての ID にテストがあります。

ピラミッド: [CONCEPT](CONCEPT.md)(なぜ)→ [SPEC](SPEC.md)(何を、ID つき)→ `core/src` と `sim/src`(どう)→ テスト(証明)。変更は下へ流れ、証明は上へ流れます。ルールは [CLAUDE.md](CLAUDE.md) にあります。

```sh
sh scripts/check.sh          # fmt、clippy、テスト、SPEC↔テストの対応、2 つの行数上限、中核の依存、バイナリサイズ
sh scripts/e2e.sh            # 中核(`sim --plain`)とエディタを tmux(専用ソケット)で
cargo test --release --workspace -- --ignored bench   # 性能要件
```

プロパティテスト、すべての側のテキストについて「失わない」モデルを持つファザー、保存の各段階での障害注入、nvim との差分オラクル、描画された画面のゴールデンが、約束を守らせています。
